# 供应链大模型 Agent 研究全景（2024–2026.08）：需求预测 / 库存优化 / 采购协同 / 异常响应 + Benchmark 清单

## 零、先给结论

1. **这条线已经成形，但成熟度极不均衡**。2023 年微软的 OptiGuide 把"LLM 当供应链优化的解释层"[1][2] 之后，2024 年才出现真正意义上的"LLM 智能体做供应链决策"（InvAgent [14]、Agentic LLMs 共识寻求 [21]），2025 下半年到 2026 上半年集中爆发，主战场从"能不能做"转向"可靠不可靠、怎么评"。
2. **四个环节的研究密度差别很大**：库存优化最热（有真正的多轮决策智能体、有基准、有行为学实验），异常/中断响应次之（多为多智能体感知—研判—处置流水线），采购协同刚起步但 2026 出现了几篇实打实的工作（合同约束求解 [27]、议价实验 [26]、集采仿真 [30]），需求预测反而最"不 agent"——绝大多数仍是把 LLM 当特征提取器或事件知识注入器 [9][10]，端到端预测智能体几乎没有。
3. **Benchmark 有，而且 2026 年一口气冒出来一批，但没有一个覆盖你问的四个环节**。目前可用的有 8 个左右（详见第三节）：SupChain-Bench [45]、AIM-Bench [46]、RetailBench [47]、MerchantBench [48]、STOCKTAKE [49]、Market-Bench [50]、CoffeeBench [51]、CSCBench [52]，再加上 InventoryBench（随 [15] 发布）、LARD-SC 风险识别评测 [35]、ISOMORPH 预测数据集生成器 [11]。**采购协同与异常响应目前只有零散的、单篇论文自建的评测，没有公共基准**。

---

## 一、总体格局与综述（先看这几篇建立坐标系）

- **奠基线**：Li 等的 *Large Language Models for Supply Chain Optimization*（OptiGuide）[1] 把 LLM 定位成"优化结果的翻译官与 what-if 问答层"，而不是决策者；其扩展版 *Large Language Models for Supply Chain Decisions* [2] 把范围推广到寻源、计划、执行全流程。这两篇是后续几乎所有工作的引用起点。
- **管理学侧的框架文献**：IJPR 2024 的能力视角框架 [3] 是生成式 AI 进供应链/运营管理最被引的框架文；2026 年 IJPR 出了系统性文献综述与应用框架 [4] 和一篇面向物流与供应链的生成式 AI 指引性综述 [5]，适合拿来做主题分类的骨架。
- **"智能体化"的概念升级**：IJPR 2026 的 *Agentic digital twins* [6] 把 agentic AI、数字孪生、基于模型的优化/仿真三者合流，提出 A-SCDT 概念与 ICARUS 框架，是目前最系统的"agent + 供应链数字孪生"概念论文。
- **运筹侧综述**：*Large Language Models in Operations Research* [7] 覆盖 LLM 做建模、求解、解释的整条链路，供应链优化是其主要落地场景之一。

## 二、按你问的四个环节做主题分类

### 2.1 需求预测（最薄弱的一环）

现状是：**LLM 在需求预测里主要扮演"上下文/事件知识注入者"和"副驾"，不是自主智能体**。

- **副驾 vs 全自动的对照实验**：IJPR 2025 用 OpenAI o1-mini 做备件需求预测，直接把"完全自动化"与"仅作副驾"两种使用方式摆在一起比 [8]。这是目前最贴近"能不能把预测交给大模型"这个问题的期刊级证据。
- **事件知识融合**：EventCast [9] 针对大促、节庆、政策突变等高冲击时段，把未来事件知识以模块化方式注入时序预测——这类"需求断点"恰恰是传统模型最容易崩的地方。
- **图学习 + LLM 引导**：LMGL-WD（AAAI 2026）[10] 用 LLM 引导多任务图学习，做电商品类级仓库需求预测。
- **中断概率预测**：*Forecasting Supply Chain Disruptions with Foresight Learning* [13] 用已实现的中断结果作监督，训练 LLM 输出**校准过的概率预测**——把"预测"从需求量扩展到"中断事件"，是异常响应与预测的交叉点。
- **数据与评测底座**：ISOMORPH [11] 是**首个公开的多echelon物流网络数字孪生**，参数可解释、拓扑/需求/控制规则可配置，专门用来生成时序预测数据集与基准——它明确指出开放时序预测基准覆盖零售、能源、气象、交通，唯独**供应链物流长期缺位**。跨域可借用的还有 Context is Key（CiK）[12]，评测"必须结合文本上下文才能预测准"的能力，与需求预测里"促销/政策/舆情"场景同构。

> 空白很明显：**没有一个公开基准直接评"LLM 智能体做需求预测"**（既要读文本上下文、又要调工具、又要对下游库存成本负责）。ISOMORPH [11] 提供了环境，但没提供 agent 评测协议。

### 2.2 库存优化（研究最密集、证据最硬）

这一环已经形成三条清晰的子线：

**(a) 多智能体补货系统**
- InvAgent [14]：最早把 LLM 当多echelon库存系统里的自主智能体，主打零样本、可解释、在需求波动场景下的适应性，是这条线被引最多的起点。
- AAMAS 2026 的 *AI Agent Systems for Supply Chains* [16]：用结构化决策提示 + 记忆检索（回溯相似历史决策）来稳定订货策略，直接回应"LLM 多智能体能不能稳定产出接近最优的订货策略"。
- Flowr [43]：超市连锁的落地型 agentic 框架，把需求预测、采购、供应商协同、补货串成一条人机协同工作流。

**(b) LLM 与运筹算法的分工（目前最有说服力的结论）**
- *AI Agents for Inventory Control: Human-LLM-OR Complementarity* [15]：构建 **InventoryBench**（1000+ 库存实例，合成 + 真实需求，压力测试需求漂移、季节性、不确定提前期），结论是**OR 增强的 LLM 方法优于任一单独方法**；并通过课堂受控实验证明**人 + AI 团队的平均利润高于人或 AI 单独决策**，还给出了个体层面受益比例的分布无关下界。这篇是目前"该怎么用"这个问题最扎实的答案。
- *Ask, Clarify, Optimize* [17]：提出"幻觉税"（hallucination tax）概念——把 LLM 当端到端求解器会因为缺乏扎实的随机推理能力而损失性能；解法是严格解耦语义推理与数学计算，LLM 只做前者。
- ORLA [20]：多仓库存分配场景，用求解器反馈来生成、验证、筛选 OR 建模方案，处理"分配要求以半结构化自然语言给出"的真实痛点。

**(c) 行为运筹：LLM 会不会犯人的错**
- *A Manager and an AI Walk into a Bar*（M&SOM）[19]：最早系统性问"ChatGPT 会不会像人一样有决策偏差"的期刊论文。
- *Large Language Newsvendor* [18]：在动态多轮报童问题上刻画主流 LLM 的认知偏差与成因。
- AIM-Bench [46]：把这条线基准化，发现不同 LLM 表现出**与人类相似、程度不同的决策偏差**，并验证认知反思与信息共享可以缓解 pull-to-centre 与牛鞭效应。
- *Reliability and Effectiveness of Autonomous AI Agents in SCM* [22]：用 MIT 啤酒游戏做多echelon实验，提出 **agent bullwhip（智能体牛鞭）** 与 **decision bullwhip** 概念——即订单波动中由智能体随机性而非真实需求变化产生的那部分；发现**重复采样这种测试时补救几乎无效**，必须改决策策略本身，并给出基于 GRPO 的强化学习后训练方案。
- *LLMs for Supply Chain Management* [23]：RAG 框架 + 领域特化 SCM LLM，通过标准化 SCM 考试与啤酒游戏测试，还用 LLM 跑横向/纵向供应链博弈分析竞争与合作。
- 群体行为侧：ACL 2026 的认知异质性研究 [24] 用 LLM 模拟多阶段供应链，专门看**智能体认知异质性**如何影响交互（此前研究多假设同质智能体）；[25] 则严肃回答一个前置问题——**生成式智能体到底能不能当人类行为的代理**，用受控实验检验 LLM 与人类行为的等价性。
- 协同机制：IJPR 2025 的共识寻求研究 [21] 把"避免牛鞭效应所依赖的人类共识过程"部分自动化，目标是让中小企业也用得起。

### 2.3 采购协同（2026 才真正起步）

- **议价与信息结构**：*Talking Terms* [26] 是这一环最重要的实证工作——让 LLM 智能体做供应链合同谈判，与人类基准实验对照，覆盖供应商成本信息**公开 / 私有 / 模糊 / 欺骗**四种情形。核心发现：LLM 用简单启发式决策、整体表现出类人议价行为，但**比人类更倾向达成协议**，结果是供应链效率更高、但分配更不平等；欺骗 LLM 让它相信成本更高会让供应商获利而损害零售商与整体效率；定制化 RAG 配置能改善谈判结果。这篇同时把伦理问题摆上台面。
- **合同条款 → 可执行计划**：Contract2Plan [27] 处理最工程化的难点——MOQ、提前期、价格阶梯、分配上限、替代料审批这些条款散落在合同与供应商文件里，纯抽取或纯 LLM 的管线很脆（漏条款、单位错、冲突未解），会在 BOM 耦合下放大成不可行计划甚至静默违约；它在 GenAI 与求解器之间插入验证层，做 BOM 感知的采购 + 多echelon库存联合规划。
- **供应商评估与选择**：Scientific Reports 2026 的多智能体供应商评估框架 [28]，用专职智能体分别处理财务健康度、风险、行业标准、市场情绪等维度，融合结构化与非结构化数据。IUI 2026 的 SCSimulator [32] 则把伙伴选择建模成多目标动态博弈，用 LLM 驱动的多智能体仿真 + 可视分析来探索。
- **中断后的采购协同**：IJPE 2026 的 *Recovering Store Brand Supply from Disruption* [29] 直接研究"AI-LLM 支持的采购协同"如何帮自有品牌供应从中断中恢复——是少见的把采购协同与异常响应打通的期刊工作。
- **谈判能力的概念梳理**：IJPR 2026 的买卖双方谈判混合智能框架 [31] 从文献与市场两侧梳理 AI 能力边界。
- **仿真环境**：ProcureGym [30] 把中国国家药品集中带量采购（NVBP）建模成马尔可夫博弈，基于 7 轮真实数据（325 个药品、2267 家企业）搭高保真环境，**同台评测 RL、LLM 与规则型智能体**——这是目前最接近"采购环节 benchmark"的公开工作。

### 2.4 异常响应 / 中断监测

- **端到端 agentic 处置流水线**：*Automating Supply Chain Disruption Monitoring* [34] 是这一环指标最完整的工作：7 个专职智能体 + 确定性工具，从非结构化新闻里检测中断信号 → 映射到多层供应商网络 → 基于网络结构评估暴露 → 推荐替代寻源等缓解措施；在 3 家汽车制造商、5 类中断的 30 个合成场景上，核心任务 **F1 = 0.962–0.991**，端到端分析平均 **3.83 分钟 / 每次 0.0836 美元**，相对行业里分析师数天的评估流程是**三个数量级的响应时间压缩**，并用 2022 年俄乌冲突做了真实案例验证。
- **模式归纳与预测**：SHIELD（EMNLP 2024）[33] 面向电动车电池供应链，LLM 驱动模式归纳建知识库 + 微调模型做事件抽取 + 多维相似度匹配 + 图卷积做中断预测。
- **稀有事件**：IJPE 2026 的 *The 1% problem* [36] 直击制造供应链里稀有事件检测的极端类别不平衡，用 LLM 编排来解。
- **世界模型式推演**：ReflectiChain / *From Topology to Trajectory* [37] 指出常规 LLM 规划器碰到"政策黑天鹅"这类非平稳事件会出现**决策瘫痪**或严重的**接地缺口（grounding gap）**，用生成式世界模型做潜在轨迹预演来补物理环境建模。
- **韧性与产能重构**：IJPR 2025 的 UNISONE 框架 [38] 做中断建模与产能优化；IJPR 2026 的多智能体风险评估 [39] 面向供应网络。
- **评测**：LARD-SC [35] 是目前唯一公开的供应链风险识别 LLM 基准——面向服务的架构，评测 5 种 LLM 变体在新闻流里检测、分类风险的能力。

### 2.5 横切线：优化建模与求解协同（供应链 agent 的"手")

- OptiRepair [40]：供应链优化模型因建模错误变得不可行时的**闭环诊断与修复**。在 976 个多echelon供应链问题上测了 7 个家族的 22 个 API 模型，训练的 8B 模型达到 **81.7% 合理恢复率（RRR）**，而最好的 API 模型只有 42.2%、平均 21.3%；差距集中在第一阶段修复（API 模型 27.6% vs 训练模型 97.2%），且**约四分之一"可行"的修复违反库存理论**。结论很实用：求解器交互靠训练补，运营合理性必须写成求解器可验证的显式检查。
- 网络优化 + LLM 的交互式可解释计划 [41]（真实案例）、生成式供应链计划范式 [42]、SustAI-SCM [44]（agentic 流程自动化，报告成本降 28.4%、碳排降 30.3%）构成落地侧的补充证据。

## 三、Benchmark 清单（直接回答"有没有"）

| # | Benchmark | 年份 / 出处 | 覆盖环节 | 任务形态 | 关键指标 / 主要发现 |
|---|---|---|---|---|---|
| [45] | **SupChain-Bench** | 2026, ACL | 供应链知识 + 长程工具编排 | 基于标准作业流程（SOP）的多步工具调用 | 各模型**执行可靠性差距巨大**；提出 SOP-free 的 SupChain-ReAct，工具调用最稳 |
| [46] | **AIM-Bench** | 2025, arXiv | 库存补货 | 多情境不确定补货实验 | 各 LLM 呈现**类人决策偏差**（framing、pull-to-centre、牛鞭）；认知反思 + 信息共享可缓解 |
| [15] | **InventoryBench** | 2026, 随 [15] 发布 | 库存控制 | 1000+ 实例，合成 + 真实需求，含需求漂移/季节性/不确定提前期 | **OR 增强 LLM > 单独 OR 或单独 LLM**；人 + AI 团队利润高于任一单独 |
| [49] | **STOCKTAKE** | 2026, arXiv | 补货（感知 vs 行动） | 26 周补货任务，因子化 POMDP，6 个隐藏因子过程，配**公平 Oracle**（同观测流上的精确贝叶斯滤波 + rollout） | skill score（0=症状盲基准，1=Oracle）；主流模型检出 84–88% 隐藏故障却 skill 从 0.62 到 **-0.23**；已正确诊断的紧张周仍有 34–43% 断货——量化"知行差距" |
| [47] | **RetailBench** | 2026, arXiv | 定价、补货、**供应商选择**、货架品类、库存老化、现金流 | 单店超市 180 天（可支持千日级）部分可观测仿真 | 相对 Oracle 策略比最终净值与销售；7 个模型均暴露证据获取不全、决策浅表、缺长程一致策略 |
| [48] | **MerchantBench** | 2026, arXiv | 卖家侧选品、上架与定价等 4 类相互依赖决策 | 订单级仿真（论文称基于 98,843 个真实电商商品），延迟异质反馈 | 专测**长程一致性（Long-Term Coherence）** |
| [50] | **Market-Bench** | 2026, arXiv | **采购（竞价）+ 零售定价/营销** | 可配置多智能体供应链经济体，预算受限拍卖 + 定价 | 记录竞价、价格、文案、销量、资产负债全轨迹；20 个开闭源智能体呈现**赢家通吃**，多数在盈亏平衡线徘徊 |
| [51] | **CoffeeBench** | 2026, arXiv | 跨层级（2 农户 / 2 烘焙商 / 2 零售商） | 90 天多智能体经济体，需沟通、谈判、交易 | 面向**长程 + 异质企业**的多智能体经济评测 |
| [52] | **CSCBench** | 2026, arXiv | 计划、采购、交付（大宗商品） | 2.3K+ 单选题，PVC 三维框架（Process / Variety / Cognition） | Process 与 Cognition 轴表现好，**Variety 轴（品种特定规则，尤其运费协议）显著退化** |
| [35] | **LARD-SC** | 2025, SOCA | 供应链风险识别 | 新闻流风险检测与分类 | 5 种 LLM 变体横评 |
| [11] | **ISOMORPH** | 2026, arXiv | 多echelon物流（预测） | 数字孪生模拟器 + 数据集生成 | 补时序预测基准里供应链物流的空缺 |
| [30] | **ProcureGym** | 2026, arXiv | 国家集采（采购） | 马尔可夫博弈仿真，基于 7 轮 NVBP 真实数据 | RL / LLM / 规则智能体同台比较 |
| [12] | **Context is Key** | 2024→ICML 2025 | 跨域预测（可借用） | 必须结合关键文本信息的预测 | 评"读上下文再预测"的能力 |

补充说明：
- **完全缺位的是"异常响应"与"采购协同"的公共基准**。[34] 用的是自建的 30 个合成场景，[26] 用的是与人类实验对照的自建议价场景，[29][36] 是期刊论文的自有数据——都不可复用。
- 啤酒游戏（beer game）事实上正在成为这条线的**共同事实标准**：[22][23][46] 都用它，但**各自的成本口径、需求路径、信息共享设置不统一**，跨论文数字不可直接比较。

## 四、关键指标与目前可引用的量化结论

| 结论 | 数字 | 出处 |
|---|---|---|

| 智能体牛鞭：重复采样无法有效降低运行间决策不稳定性，需改策略本身（GRPO 后训练可显著削尾部事件） | 定性 + 实验 | [22] |

## 五、研究空白（做选题可以直接接的地方）

1. **没有跨环节的统一基准**。需求预测 → 库存 → 采购 → 异常响应这条端到端链路，目前没有任何一个基准打通。RetailBench [47] 最接近（补货 + 供应商选择 + 定价耦合），但限于单店零售且不含上游多层网络与中断传播。
2. **需求预测环节的 agent 化几乎空白**。现有工作要么是 LLM 做特征/事件注入 [9][10]，要么是副驾式使用 [8]，**没有"自主调工具、读非结构化上下文、对下游库存成本负责"的预测智能体评测**。ISOMORPH [11] 提供了环境但缺 agent 协议。
3. **采购协同缺公共环境**。ProcureGym [30] 是集采单一场景；Market-Bench [50] 的采购只是预算受限拍卖；真实的多轮供应商谈判 + 合同条款约束 + BOM 耦合（[27] 的问题设定）还没有基准化。
4. **可靠性而非平均性能才是瓶颈**。[22] 的 agent bullwhip、[49] 的知行差距、[40] 的"可行但不合理"修复，三篇从不同角度指向同一件事：**平均表现好掩盖了运行间方差与静默违规**。评测指标应从"平均成本"转向"尾部事件率 + 违规率 + 运行间稳定性"。
5. **偏差是特性还是缺陷没定论**。[18][19][46] 证明 LLM 会复刻甚至放大人类认知偏差；[24] 进一步指出智能体间的认知异质性会改变系统动力学。但"要消除偏差以逼近最优"还是"要保留偏差以模拟真人"取决于用途——[25] 恰恰提醒：把生成式智能体当人类代理这件事本身还需要验证。
6. **缺少与传统方法的严格头对头比较**。除 [15] 明确做了 OR vs LLM vs 人的对照、[30] 做了 RL vs LLM vs 规则的对照外，大多数论文只与提示词消融或弱基线比，**没有与深度强化学习、(s,S) 策略等成熟基线在同一环境同一成本口径下比较**。
7. **治理与自治边界**。[6] 提出 agentic 数字孪生概念后，自治程度评估、人在环节点设计、审计与合规仍是空白（Flowr [43] 只给了工程化的人机协同流程，没有可度量的自治框架）。
8. **中文场景与本土数据严重缺位**。除 ProcureGym [30]（中国集采）外，公开学术工作几乎都是欧美/合成数据；中文侧目前主要是企业实践材料而非同行评议研究。
