# 银行联合风控中的联邦学习：隐私保护与特征不一致是如何被同一套机制同时解决的

## 〇、先把问题拆开：两个"不一致"，三层"隐私"

银行做联合风控时，"特征不一致"其实是三件不同的事，对应三套不同的机制，混在一起谈会得出错误结论：

- **不一致 A：特征空间互补而不重叠**。甲行有存贷流水，乙行/运营商/电商有另一批变量，客户群却大量重叠。这是"纵向切分"，对应纵向联邦学习（Vertical FL, VFL）[1][2]。
- **不一致 B：同名特征口径与分布不一致**。两家行都有"月均余额"，但取数口径、客群结构、坏账定义不同，形成 non-IID 的特征/标签漂移。这属于横向联邦下的统计异构问题 [24][25]。
- **不一致 C：特征块整体缺失、样本只部分对齐**。某方在推理期拿不到某些特征，或两方交集样本极少。这需要缺失鲁棒、半监督/自监督与联邦迁移机制 [19][20][21][22]。

"隐私保护"同样是三层，机制上是分层落地的：

1. **样本层**：谁是共同客户？名单本身就是商业机密 → 隐私求交（PSI）/实体解析 [4][5][6][7]。
2. **训练层**：中间量（梯度、二阶导、embedding）不能反推原始特征或标签 → 同态加密、秘密分享、函数加密、差分隐私 [10][13][16]。
3. **推理与残余泄露层**：即使全程加密，模型输出与多轮交互仍可能泄露标签或特征 → 攻击面研究与针对性防御 [29][30][31][32][33]。

下面按"数据流顺序"给出机制，并标注论文依据。

---

## 一、总体范式：为什么银行场景默认落在"纵向联邦"

Yang 等人给出的三分类是全部后续工作的坐标系：横向联邦（特征空间相同、样本不同）、纵向联邦（样本重叠、特征互补）、联邦迁移（样本与特征都很少重叠）[1]。银行与银行之间若客群差异大、字段大体相同，属于横向；银行与运营商、电商、税务、征信机构之间客群重叠而字段互补，属于纵向；跨地域、跨业态的小行与大行合作则常常落在联邦迁移。

纵向联邦的完整技术地图（对齐、切分、加密、通信、激励、攻防）由 Liu 等人的 TKDE 综述系统整理 [2]；工程形态上，工业界最常被复现的是 FATE 平台，它把 PSI、Hetero-LR、SecureBoost、SplitNN 等模块化成可部署的协议栈 [3]。金融侧的技术选型与瓶颈综述可参考 [38]，开放银行语境下的数据所有权与联邦建模讨论见 [37]。

## 二、模块 A：样本对齐——在不暴露客户名单的前提下确定"同一个人"

这是所有纵向联邦的第一步，也是最容易被忽略的隐私缺口。

**基础机制（隐私求交 + 加法同态加密）。** Hardy 等人 2017 年的工作是这条线的奠基：先用加密的实体解析（entity resolution）确定共同记录，再用 Paillier 加法同态加密在纵向切分的数据上训练逻辑回归，双方只交换密文中间量 [4]。这套"PSI → 加密训练"的两段式，至今仍是 SecureBoost、Hetero-LR 等的默认前置流程。多方（>2）场景下的 PSI 构造见 [5]。

**关键改进 1：交集成员身份本身也要保护。** 标准 PSI 会让参与方知道"哪些 ID 落在交集里"。当两方规模悬殊（大行 vs 小机构）时，小方的 ID 清单是稀缺资产。非对称纵向联邦提出在 ID 对齐阶段就对小方做保护，使大方无法枚举小方的全部 ID [6]；[7] 进一步给出带差分隐私保证的非对称 ID 对齐协议，使交集之外的 ID 也获得形式化的隐私上界。

**关键改进 2：真实银行数据往往没有干净的公共主键。** 跨机构常见的是姓名+地址+手机号的模糊匹配，硬匹配会引入链接噪声。FedSim 的做法是不做"先硬匹配再训练"，而是把记录相似度直接耦合进模型：对每个样本取跨方 top-K 近邻，按相似度加权聚合其表示，端到端训练 [8]。多方模糊链接的最新方案 Federated Transformer 用 Transformer 编码跨方近邻集合，并配合可训练动态掩码与差分隐私，在链接噪声下同时兼顾精度与隐私 [9]。**这一支文献正是"特征不一致"的上游对应物——实体不一致。**

## 三、模块 B：特征空间不一致（纵向切分）下的加密训练机制

### B1. 树模型：SecureBoost 的完整数据流（最常被银行采用）

以持有标签的主动方（active party，通常是发起风控的银行）和若干被动方（passive party）为例，SecureBoost 的一轮迭代是 [10]：

1. 主动方在本地按当前模型算出每个样本的一阶导 `g_i` 与二阶导 `h_i`，用 Paillier 加法同态加密得到 `[[g_i]]`、`[[h_i]]`，广播给被动方。
2. 每个被动方对**自己的**特征做分位数分桶，在**密文域**按桶累加，得到密文直方图 `Σ[[g]]`、`Σ[[h]]`，回传主动方。加法同态保证被动方全程看不到 `g,h` 明文，也就看不到标签。
3. 主动方解密后，用 XGBoost 的增益公式在所有方、所有候选分裂点上选全局最优，把 `(参与方 id, 特征桶索引)` 告知对应被动方。
4. 被动方在本地查表得到真实的 `[特征, 阈值]`（只留在本地的 lookup table 里），把该分裂下左右子节点的样本 ID 集合返回。主动方因此只知道"由哪一方的第几个查表项决定"，不知道是哪个特征、什么阈值。
5. 推理时逐节点向对应方查询走向，模型天然是分布式的。

由于每一步都与集中式 XGBoost 数学等价，作者称其为 **lossless**——这是它在信贷风控被接受的关键：模型效果不因加密而打折。代价是 Paillier 密文运算极慢，VF2Boost 通过定制的密文流水线、并行分桶与 GPU 加速把纵向联邦 GBDT 的训练时间压到可用量级 [11]。

### B2. 线性模型与评分卡：合规可解释路线

银行零售信贷仍大量使用评分卡，联邦化的重点是"既加密又保持评分卡形态"：

- **纵向逻辑回归的加密梯度分解**：把 `w^T x` 拆成各方局部内积之和，各方交换加密的局部结果与残差；用拟牛顿（Quasi-Newton）方法替代一阶 SGD，可显著减少加密通信轮数 [12]。
- **混合密码学协议**：纯同态加密开销大、纯秘密分享通信重，蚂蚁集团在 KDD 2020 给出 HE 与秘密分享混合的方案，专门针对大规模稀疏逻辑回归，并直接以风控为落地场景 [13]。
- **面向风险管理的同态加密纵向联邦系统**：把贝叶斯类模型放进纵向联邦，原始数据不出域、只交换加密模型信息，实测精度可达单机集中训练的九成左右，明确指向风控场景 [14]。
- **可解释联邦评分卡**：FL-LRBC 在纵向联邦下训练**带边界约束**的逻辑回归，约束保证 WOE 分箱后系数符号与单调性成立，从而仍能导出传统评分卡，满足审计与解释要求 [15]。

### B3. 神经网络与第三方问题

深度模型走 SplitNN 形态：被动方只上传底部模型输出的 embedding，主动方持顶部模型与标签。工程上一个长期痛点是很多协议依赖"可信第三方协调者"，银行合规上很难接受。FedV 用函数加密（functional encryption）在纵向切分数据上做安全聚合，**取消了对可信第三方的依赖**，同时减少了参与方之间的交互轮数 [16]。

### B4. 特征质量与"合并口径"

多方拼特征不等于特征越多越好。VertiBench 指出：现有 VFL 评测的"特征怎么分给各方"高度单一，作者用**特征重要性不平衡度**与**跨方特征相关性**两个维度合成划分，发现算法排名对划分方式极其敏感 [17]——这是把"特征不一致"量化的第一份系统性工作，做行内联合建模的可行性评估时应先跑这两个维度。在此基础上，FedSDG-FS 用高斯随机对偶门控在密态下做安全特征选择，剔除噪声与无关特征，同时降低通信量与泄露面 [18]。

## 四、模块 C：三类"特征不一致"的具体解法

**C1｜特征互补但交集样本太少。** FedCVT 用半监督的跨视图训练：为非对齐样本估计缺失方的表示并生成伪标签，从而把训练集从"交集样本"扩展到"并集样本"[19]。FedHSSL 进一步先用各方**非重叠**的本地样本做跨方自监督预训练，再用少量对齐样本做表示对齐与微调 [20]。当特征与样本都只有很小重叠时，Secure Federated Transfer Learning 在公共表示空间对齐两方特征，并用加法同态加密与多项式近似在密文下训练，同时给出 HE 与秘密分享两套安全协议 [21]。

**C2｜特征块整体缺失（训练期或推理期）。** 现实中"某分支行拿不到征信侧字段"是常态。LASER-VFL 通过任务采样与共享表示，使模型对**任意可用特征子集**都能推理，而不是只在特征齐备的样本上可用 [22]。

**C3｜参与方模型与算力异构。** Flex-VFL 允许各方使用不同的本地优化器、不同的本地步数与学习率，并给出收敛性分析，避免"最慢的一方决定整体节奏"[23]。

**C4｜同名特征口径与分布不一致（横向侧）。** 这是行际横向联合最典型的问题。FedProx 通过在本地目标上加近端项限制本地模型偏离全局模型，容忍系统与统计异构 [24]；[25] 用大规模实验刻画了 non-IID 数据孤岛下各类联邦算法的实际退化幅度与适用边界，是做可行性预判的基线参考。金融专门场景上：[26] 用知识迁移改造联邦信用评分，处理各行样本与分布差异；FedVI 直接针对"特征空间异构 + 样本重叠率低"这一金融风控组合，用异构表格数据的视觉表示与元优化来桥接 [27]；[28] 则实证了类别不平衡在联邦信贷风险预测中的放大效应——这在坏账率差异大的行际联合中尤为关键。

## 五、模块 D：加密 ≠ 安全，机制的已知攻击面

若答案只讲"同态加密所以安全"，会漏掉近年最重要的一批机制研究：

- **标签推断攻击**：被动方可利用底部模型结构与梯度更新机制反推主动方私有标签，甚至推断训练集之外的标签 [29]。
- **特征推断攻击**：攻击者可从模型**预测输出**反推被动方特征，作者对逻辑回归、决策树、神经网络分别给出等式求解、路径限制与生成式回归三类攻击 [30]。
- **预测阶段的系统性泄露分析**：[31] 系统刻画了 VFL 在推理阶段的隐私泄露面。
- **纵向逻辑回归的隐私边界**：[32] 证明小批量梯度下降的纵向逻辑回归即使配合加密，多轮交互仍可被求解出敏感信息——直接挑战"Hetero-LR 天然安全"的常见假设。
- **防御机制**：HashVFL 对上传的 embedding 做二值哈希，切断数据重构攻击的梯度通路，同时保持可用性 [33]。

工程结论：银行联合风控的隐私设计必须是"PSI + 密态训练 + 输出侧防护（embedding 处理/差分隐私/查询频次限制）"的组合，而不是单点加密。

## 六、银行侧的落地与实证依据

- **纵向联邦在银行风控模型策略中的应用研究**：给出了行内落地的模型策略与流程设计 [34]。
- **Starlit**：英美 PETs Prize Challenge 的获奖方案，支付网络与多家银行联合做金融欺诈检测，是少数公开的"多机构真实拓扑 + 隐私增强技术"完整方案 [35]。同一挑战赛背景下的混合联邦框架（银行之间横向 + 银行与支付网络之间纵向）见 [36]，它明确处理了"不同机构持有不同字段"与"同类机构持有同类字段"并存的混合结构，最贴近真实的银行联合风控拓扑。
- **开放银行语境下的联邦学习**：数据所有权、激励与部署约束 [37]。
- **金融数据孤岛的技术路线综述**：[38] 对各类金融联邦场景的关键技术做了近期梳理。
- **联邦图学习用于金融犯罪协同侦测**：把跨机构交易网络当作图来做联邦建模，是"特征不一致"在关系型数据上的变体（各方持有同一批账户的不同边与属性）[39]。

## 八、给"讲机制的论文"的最短阅读路径

1. 先读 [1] 建立三分类坐标，再读 [2] 补全纵向联邦全景。
2. 机制原型读 [4]（PSI + Paillier 的两段式）与 [10]（SecureBoost 的完整密态数据流）。
3. 银行可解释性诉求读 [15]，性能可行性读 [11][13]。
4. "特征不一致"专题读 [17]（怎么量化）、[8][9]（实体不一致）、[19][20][21][22]（重叠不足与缺失）、[27]（金融场景的组合难题）。
5. 上线前必读攻防四篇：[29][30][32][33]。

**一句话回答**：联邦学习并不是用一个机制同时解决两件事，而是把"特征不一致"转成纵向切分的模型分解问题（各方只算自己特征上的局部量），再用密码学机制（PSI + 同态加密/秘密分享/函数加密）保证这些局部量在交换过程中不可反推——隐私保护与特征互补因此在同一条数据流上被同时满足；而口径漂移、样本重叠不足、特征块缺失这三类"不一致"则各自有独立的补丁机制，需要按场景叠加。
