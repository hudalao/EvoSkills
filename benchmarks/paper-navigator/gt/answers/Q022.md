# 矿井按需通风（VOD）中"传感器反馈 + 模型预测控制"的闭环实现机制

## 一、先给结论

矿井按需通风领域里，**真正把"传感器反馈 + 模型预测控制（MPC）"写成完整闭环并给出数学形式和现场数据的论文只有少数几篇**，绝大多数文献停在其中某一个环节（只做感知重构、只做网络解算、只做需风预测、或只做启发式寻优）。就"具体怎么实现"这个问题，最值得精读的是下面四篇，它们分别代表四种不同的闭环形态：

| 代表论文 | 闭环形态 | 控制律 | 验证级别 |
|---|---|---|---|
| [1] 数字孪生 + LSTM-Attention + 自适应 MPC | 预测型 MPC（滚动时域 + QP） | 显式二次型 MPC | 现场 8 个月 |
| [2] Boliden Garpenberg 优化模型化控制 | 数据驱动动态模型 + 全矿多变量协调控制 | 带约束的多变量最优控制 | 工业投运 |
| [4] DL-Koopman 预测 + 模糊自适应 PID | 预测 + 增益自整定反馈 | Fuzzy-PID | 深部矿井案例 |
| [3] 神经模糊（neuro-fuzzy）VOD 模型 | 数据驱动模型 + 实验闭环 | 神经模糊控制器 | 实验室尺度台架 |

下面按"数据流从传感器到执行器"的顺序拆解各个模块的机制，每一处都给出论文依据。

---

## 二、闭环回路的整体结构

矿井 VOD 闭环控制的通用数据流是五段式：

```
① 感知层        ② 状态估计/网络解算       ③ 预测层            ④ 决策层(MPC)         ⑤ 执行层
风速/风压/瓦斯   稀疏测点 → 全网风量重构   需风量、风量、瓦斯    滚动时域优化          主扇变频、局扇变频
温湿度/CO/NOx →  风阻在线反演/模型标定  →  浓度的多步超前预测 →  求解带约束QP        →  风窗开度、风门角度
人员车辆标签     (Hardy-Cross/割集/PINN)   (LSTM/Koopman/VMD)    得到 u*(t)            (SCADA→PLC)
      ↑                                                                                     │
      └─────────────────────── 实测量回传，形成闭环（周期 30 s ~ 数分钟） ────────────────────┘
```

中文文献里把这条回路概括为"**动态感知—自主决策—精准执行**"的闭环，并且明确把它作为矿井智能通风的核心目标 [33][34]；国际文献里对应的概念是 VOD 的分级（Level 1 人工远控 → Level 2 时间表 → Level 3 事件触发 → Level 4 标签跟踪），Totten 矿的实现报告给出了 Level 4 的具体构成 [25]。俄语系文献把同一件事叫 AVCS（自动通风控制系统），与西方 VOD 的关键差别正是"是否用最优控制算法自动确定风机与风门的工作参数" [26]。

## 三、逐模块机制与论文依据

### 3.1 感知层：测什么、测多少、装在哪

**测什么。** [1] 给出了一个可复现的完整清单：全矿 68 个测点，每点配超声波风速仪（Gill WindSonic，0–60 m/s，±2%）、压阻式压差传感器（Honeywell 26PC，0–5 kPa，±0.25%）、PT1000 铂电阻温度传感器（±0.1 °C）、甲烷传感器（Dynament IRM-AT，检出限 0.01% CH₄，±5% 读数），经 LoRaWAN（SX1276，470–510 MHz）汇聚到 15 个边缘计算节点，采样周期 30 s。[7] 的 CPS 架构则把能耗表、控制器与风环境参数三类数据源统一接入，[6] 用长距离无线模块采集气体浓度并直接驱动 VOD 模块。

**装多少、装在哪——这是 VOD 落地最实际的约束。** [13] 提出"独立割集（independent cut set）"概念，把传感器最少数量与位置问题转化为图论问题：在某晋煤集团矿井（巷道数 > 200）验证，**只需不到 30% 的巷道布设风速传感器，即可把全网风量重构出来，且重构风量与实际风量一致**。这是"稀疏感知 → 全网状态"的关键机制。控制理论侧的对应结论来自 [9]：在小型矿山中"每条分支一个传感器 + 一个执行器"的理想配置不现实，论文明确把传感器/执行器数量作为约束条件来设计反馈控制器，并在实验台上比较了三种经典控制策略在传感器受限下的表现；[10] 进一步给出不为每条巷道配自动风门时、直接控制部分分支风量的非线性模型与控制策略。

### 3.2 状态估计与网络解算：把稀疏读数变成全网状态

这是 MPC 能工作的前提——MPC 需要一个"当前状态 + 预测模型"。矿井通风的物理模型是有向图上的三条方程：节点风量平衡 ΣQᵢ = 0、回路风压平衡、以及巷道阻力平方定律 h = R·Q² [1]。

- **实时解算。** [1] 的虚拟模型层维护 156 条巷道、89 个节点的网络，用 Hardy-Cross 迭代法实时求解非线性风量分配方程，把实测风量与网络拓扑约束调和一致，作为 MPC 的状态输入。[23] 用节点风压法结合 Hardy-Cross 解算建立训练库，再用机器学习/深度学习模型由少量已知测点推断未知点的风流参数。
- **摆脱风阻实测。** 风阻 R 是全网解算的核心参数，但现场逐条巷道测阻成本极高。[14] 提出**无需风阻实测的实时网络解算**方法；[16] 用深度强化学习增强风阻系数反演；[15] 用非线性优化算法标定通风网络模型，使仿真风量分布与实测数据一致、同时把其它参数误差压到最小（基于实际通风阻力测定 + Ventsim 建模的真实案例）；[19] 则用连续监测的风量数据来实验性地改进通风网络模型。
- **数据稀疏下的场重构。** [17] 用物理信息神经网络（PINN）嵌入涡粘系数 νt 湍流建模、配合 Fluent 生成的流场数据，在稀疏数据条件下重构并预测工作面风流场；[18] 用 CNN-MLP 混合架构做金属矿风流参数的数据驱动感知。
- **数据清洗。** [1] 在数据层用三西格玛离群检测 + 卡尔曼滤波剔除电磁干扰与传感器漂移造成的异常读数，并做时间戳对齐，存入 InfluxDB 时序库——这一步在实际闭环里不可省略，否则脏数据会直接被 MPC 当作真实偏差去追。

### 3.3 预测层：MPC 的"模型"从哪来

MPC 的核心区别于 PID 的地方，就是它显式使用一个能预测未来的模型。矿井场景下这个模型有两条技术路线：

- **数据驱动的黑箱/灰箱动态模型。** [2] 的做法最"工程"：模型是数据驱动的，直接由历史运行数据或**阶跃变化实验**辨识得到；论文特别强调这样做使初次部署和随矿井演化的模型维护都变得容易，实测表明控制器长期稳定运行而不需要重新标定模型。
- **深度学习时序预测。** [1] 用 LSTM-Attention 混合网络，输入过去 60 个时间步的数据序列，输出通风参数的多步超前预测，MAPE 2.87%、R² 0.9612。[31] 用鲸鱼算法优化的 VMD 加深度学习混合模型做矿井风量的超前预测。[4] 走的是算子学习路线：用 DL-Koopman 算子在风速波动等动态工况下预测瓦斯浓度。隧道施工场景的同类做法见 [30]，用 STA-CNN-ResBiLSTM 预测污染物浓度并直接驱动需求控制通风；地下隧道群施工的按需通风控制系统实现见 [32]。
- **需风量预测（VOD 的"设定值"从哪来）。** VOD 的设定值不是常数，来自生产活动：柴油设备位置与负荷、人员标签、爆破时刻、瓦斯涌出。[25] 描述的 Level 4 标签跟踪就是把人员/车辆位置和类型转成需风量；[27] 综述了 AI 进入 VOD 后设定值生成方式的变化。

### 3.4 决策层：MPC 到底怎么写

[1] 给出了矿井通风 MPC 目前最完整的显式表述，可以直接照着实现：

**（1）滚动时域二次型目标**

```
min_{u(t:t+Np)}  Σ_{k=0}^{Np} ‖ y(t+k|t) − y_ref(t+k) ‖²_Q  +  Σ_{k=0}^{Nc−1} ‖ Δu(t+k) ‖²_R
s.t.   u_min ≤ u(t+k) ≤ u_max ,   y_min ≤ y(t+k|t) ≤ y_max
```

其中 Np、Nc 为预测时域与控制时域，Q、R 为正定权阵，Δu 为控制增量。y 是风量/浓度等被控输出，u 是风机转速与风窗开度。

**（2）能耗—安全联合目标**

```
J_energy = ∫₀ᵀ [ P_fan(t) + α·max(0, C_CH4(t) − C_limit) ] dt
u*(t)    = argmin_u { J_energy + J_tracking }
s.t.  u_min ≤ u ≤ u_max ,  Δu_min ≤ Δu ≤ Δu_max ,
      Q_min ≤ Q ≤ Q_max ,  CH₄ ≤ 0.75% ,  n_min ≤ n ≤ n_max ,  |Δn| ≤ Δn_max
```

α 是安全约束违反的罚系数；论文中三项权重经验整定为 w₁ = 1.0、w₂ = 2.5、w₃ = 0.5，即刻意把安全权重压过节能权重。注意 P_fan 与转速三次方成正比，这正是 VOD 节能的物理来源。

**（3）前馈补偿**

```
u_ff(t) = G⁻¹ [ y_ref(t+h) − ŷ(t+h) ]
```

G 为稳态增益矩阵，ŷ 由 LSTM-Attention 预测器给出，h 为预测时域。这一项让控制器在偏差还没在物理系统里显现之前就动作，是"预测"真正发挥作用的地方。

**（4）在线求解。** 每个控制周期求解一个**带约束的二次规划（QP）**，在权衡跟踪精度、能耗与安全裕度之后输出最优控制序列，只执行第一步，下周期重新求解。

**（5）与 Boliden 工业实现的对照。** [2] 没有把自己写成教科书 MPC，但机制同源：用风量测量 + 通风系统动态模型做**全矿范围的风机协调控制**，在满足风量设定值的同时不违反"风机两端最小/最大压差"和"区域间串风"等约束——这正是 MPC 的约束处理能力在工业现场的价值所在。它是在既有 VOD 系统之上叠加的一层优化控制。

**（6）机制上的近邻参考。** 道路隧道与地下车站通风的 MPC 比矿井成熟得多，做矿井实现时值得直接借鉴其时延与约束处理：[28] 把 MPC 与模糊控制结合用于道路隧道通风系统；[29] 针对地下车站给出模型预测能量控制。

### 3.5 执行层：调什么、调多少、按什么顺序调

矿井通风的执行器有两类，**风机变频（主扇/辅扇/局扇）**与**风阻调节（风窗、风门、百叶）**，两者动态特性差别很大，这是矿井 MPC 与 HVAC MPC 最大的不同。

- **调节量的确定。** [20] 提出的 RPOD（rapid, precise, on-demand）理论定义了目标分支、主动分支、被动分支三个概念，按灵敏度对主动分支排序，再用灵敏度衰减率理论与最小风量原则算出主动分支的调节范围，在山西武阳煤矿验证。[22] 进一步提出**灵敏度变化率矩阵**，用拉格朗日插值优化"风量灵敏度—风阻"关系，用回路风量法确定风阻可调范围，建立多分支风量调度模型。[21] 专门处理 VOD 变化过程中分支风量的智能安全调节问题——即调节过程本身不能把别处的风量拉到不安全区间。
- **执行时延与执行器排序。** [1] 给出的端到端时延分解非常有参考价值：数据采集 30 s 采样 + 1.8 s 无线传输 → 边缘处理 0.4 s → LSTM 推理 0.18 s（GPU）/1.5 s（CPU）→ MPC 的 QP 求解 1.8 s → 执行器动作 2.5 s（风机调速）/6 s（风窗定位），**整个决策周期约 40–48 s**。风窗比风机慢一倍多，这个差异必须进 MPC 的执行器模型。
- **指令下达通道。** [1] 的连接接口层把优化结果翻译成可执行命令，经 SCADA 协议送到 PLC，下发风机转速设定值与风窗位置调整量。
- **主通风机切换这一特殊工况。** [12] 单独建模了主通风机切换系统（一台工作、一台备用，各配垂直与水平风门）的动态并设计控制器，保证切换过程中通风不中断。

### 3.6 系统架构：把上面五段装进一个可运维的系统

- **数字孪生。** [1] 用五维数字孪生架构（物理实体层、数据层、虚拟模型层、服务应用层、连接接口层）实现物理通风网络与虚拟模型的双向同步；控制动作改变物理系统状态 → 传感器捕获 → 逐层上传 → 更新预测 → 精化控制策略，形成自调节闭环。[5] 在 IEEE Transactions on Industry Applications 上给出面向实时 VOD 的智能数字孪生框架。[7] 更早提出 IoT + 数字孪生的通风控制架构，CPS 由物理对象、IoT 网络与计算基础设施、数字孪生、用户界面四个子系统构成，并且在主扇控制信号的动态计算中显式考虑了**自然风压**与**通风系统惯性**——这两项在矿井里不可忽略，是 HVAC 模型直接搬过来会失效的原因。
- **CPS 落地原型。** [6] 给出一个可运行的 CPS 原型：长距离通信模块采集气体浓度 → 形成井下态势感知 → VOD 模块 + 能耗评估模块共同驱动通风系统的动态控制。
- **中文体系文献。** [33] 给出感知—传输—决策—执行反馈四段式智能通风闭环架构，并以"基于风网调节的非线性优化模型"平衡节能与调控要求；[34] 提出矿山 4DGIS 平台 + 物联网感知与执行 + 网络解算与需风预测 + 闭环调控的四层结构；[35] 建立主通风机调频、关联分支调阻及两者联合调节的数学模型与供需匹配调控模型，用元胞自动机计算最佳调节巷道，并做了供需匹配实验——实验结论很实用：**单纯风机调频引起的风网波动最小**，分支调阻或联合调节引起的波动更大。

## 四、非 MPC 但同源的控制理论线（做对照用）

如果只关心"闭环"而不限定 MPC，矿井通风控制有一条独立的控制论脉络，建议一并看，因为 MPC 的稳定性与可控性论证往往要回到这里：

- [8] 是这条线的源头文献，在 Systems & Control Letters 上给出矿井通风网络的非线性控制方法，后续小型矿山控制、流体网络控制的论文基本都引它。
- [9] 由守恒律确定线性模型结构，给出离散状态空间模型的建模指引，然后在传感器数量受限的条件下比较三种经典控制器，并用实验台做实验与仿真对照。
- [10] 面向小型矿山提出非线性模型 + 直接控制部分分支风量的策略；[11] 用保功率守恒的物理建模方法分析小型矿井通风网络的结构性质。
- [4] 用模糊自适应 PID 做风量调节，配合 DL-Koopman 预测器，属于"预测 + 反馈"但控制律不是 MPC。
- [3] 用神经模糊模型做 VOD 建模，并做了实验室尺度的实验验证——这是目前少见的把 VOD 控制器搬上物理台架验证的工作。
- 综述性定位：[26] 系统对比了 AVCS 与 VOD 两条技术路线并给出乌拉尔分院的最优控制算法；[27] 综述 AI 进入 VOD 的现状与前景；[24] 是把 VOD 与分时电价耦合做风机转速优化的高被引起点。

## 五、读这批文献时要注意的三个空白

1. **"MPC"这个词在矿井通风里被用得很松。** 大量标题含"预测控制"的矿井论文实际做的是"预测 + 规则/启发式寻优"，没有滚动时域优化与约束处理。目前能查到显式写出 QP 形式、时域参数、约束集合并给出现场数据的，主要是 [1]；工业级但表述为"多变量优化控制"的是 [2]。
2. **模型失配是主要风险，且矿井比建筑严重得多。** 巷道拓扑随开采不断变化、风阻随支护与积尘变化。[2] 用数据驱动模型 + 阶跃试验降低维护成本，[15][16][14][19] 从不同角度解决在线标定与风阻辨识，这一组文献应该和 MPC 论文配套读。
3. **执行器与安全约束的耦合。** 风窗调节会把风量"推"到别的分支，形成全网耦合扰动，因此调节顺序与幅度本身就是安全问题——[21][20][22] 三篇正是处理这一点，把它们的灵敏度模型嵌进 MPC 的约束集合，比单纯加大权重更有效。
