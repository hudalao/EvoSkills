# 低空无人机群调度中的避碰与动态重规划：时空图与强化学习的具体机制

## 0. 先把问题拆到正确的层级

低空(UTM / U-space / UAM)里的"避碰"和"动态重规划"从来不是一个算法在做，而是三个时间尺度上的三套机制在配合。看论文时先认清一篇属于哪一层，机制才对得上：

| 层级 | 时间尺度 | 决策对象 | 主流方法 | 输出 |
| --- | --- | --- | --- | --- |
| 战略层(pre-flight / strategic deconfliction) | 分钟到小时 | 起飞时刻、航路、速度剖面 | **时空图搜索**、整数规划、多智能体路径规划(MAPF) | 4D 航迹 / 运行体(operational volume)契约 |
| 战术层(tactical deconfliction / separation assurance) | 秒级 | 机动指令(航向、速度、高度增量) | **强化学习**、速度障碍、MPC | 在线避让机动 |
| 执行层(execution / plan repair) | 百毫秒到秒 | 是否等待、是否局部改线、是否整体重解 | 动作依赖图、滚动时域、局部修复(LNS) | 保序执行或新方案 |

这个分层在 UTM 冲突探测与解脱的综述里被系统梳理过 [34]，MAPF 侧的经典/学习两条路线的对照可看 [35]。下面按"时空图这条线"和"强化学习这条线"分别讲机制，最后单独讲动态重规划。

## 1. 时空图这条线：避碰是怎么被"编码"掉的

### 1.1 基本对象：时空图与预约表

把空域离散成节点集 `V`（栅格 / 航路点 / 走廊上的采样点），时间离散成步长 `Δt`，每个节点复制成时间副本 `(v, t)`。边有两类：移动边 `(u,t) → (v,t+τ)`，等待边 `(v,t) → (v,t+1)`。于是"避碰"被翻译成两条纯图论判据：

- **顶点冲突**：两架无人机占用同一个 `(v,t)`；
- **边冲突/交换冲突**：两架在同一时间步互换 `(u,v)` 两个节点。

最早把这套东西做成可用算法的是 Cooperative Pathfinding [1]。它引入的**预约表(reservation table)** 是整条技术线的原点：按某个优先序，每架依次在时空图上跑 A\*，找到路径后把自己经过的所有 `(v,t)` 写进预约表；后规划的飞机把表里已被占用的时空点当成障碍。文中三个算法分别对应三个至今仍在用的机制——CA\*(在时空里搜)、HCA\*(用忽略时间的抽象距离当启发式，避免时空 A\* 的启发式失真)、**WHCA\***(只在长度为 `w` 的滑动窗口内做时空协调，窗口外退化成普通 A\*，窗口向前滚动后重算)。WHCA\* 就是"滚动窗口动态重规划"的最早形态。

**关键模块**：空域离散化 → 时间展开 → 单机时空 A\* → 预约表写入/查询 → 优先序决定谁先占资源。

### 1.2 CBS：把冲突变成可回溯的约束

预约表法的毛病是不最优、不完备（优先序错了就无解）。Conflict-Based Search [2] 换了个思路，做成两层：

- **高层**在一棵**约束树(CT)** 上做 best-first 搜索。每个 CT 节点携带一组约束和一组当前路径，代价取路径代价之和。取出代价最小的节点，模拟执行所有路径，找到**第一个**冲突 `⟨aᵢ, aⱼ, v, t⟩`，分裂出两个子节点：一个加约束"`aᵢ` 不得在 `t` 占用 `v`"，另一个加"`aⱼ` 不得在 `t` 占用 `v`"。
- **低层**只对被新加约束的那一架重跑带约束的时空 A\*——约束的作用就是把若干 `(v,t)` 从可扩展状态里剔除。

这个"冲突 → 约束 → 单机重规划"的循环是整个领域的核心范式：它把一个指数级的联合空间搜索，变成"只在真正发生冲突的地方才付出分支代价"。低空场景里 CBS 及其变体几乎是所有战略去冲突原型的骨架。

问题定义层面必须配一篇 [3]：它把冲突类型（顶点、边、交换、跟随、循环）、目标函数（makespan 还是 sum-of-costs）、到达目标后是否消失等隐含假设全部显式化并给出基准集。低空里"最小水平/垂直间隔"到底编码成哪一类冲突，直接决定方案保守程度，读方法论文前先对齐这套语义。

### 1.3 时间离散化的代价，以及 SIPP / CCBS 怎么解决

`Δt` 取细则时空图规模爆炸，取粗则间隔被迫保守——这是时空图落到真实无人机上的第一道坎。

**SIPP** [4] 的机制是把时间维**压缩**掉：对每个位置，把被动态障碍占用的时间段挖去，剩下的每一段极大连续可通行时间叫一个**安全区间(safe interval)**；状态从 `(位置, 时刻)` 变成 `(位置, 安全区间)`，扩展时只算"最早可到达时刻"。状态数因此正比于动态障碍段数，而不是时间步数，还天然支持等待动作。

**CCBS**(Multi-Agent Pathfinding with Continuous Time) [5] 把 SIPP 塞进 CBS 的低层，得到连续时间 MAPF：冲突不再是"同一时刻同格子"，而是"两个带几何体积的运动在连续时间上重叠"；由此推出的约束是**不安全区间**——"`aᵢ` 不得在 `[t₁, t₂)` 内发动动作 `m`"；低层用 SIPP 在禁止区间之外找最早可行的发动时刻。这样才允许**非均匀速度、非单位时长动作、任意 roadmap**，也就是真实空域走廊图所需要的形态。

再往下一层是动力学：**K-CBS** [6] 把 CBS 低层换成基于采样的动力学可行运动规划器，高层约束变成"在某时间区间内避开另一机体扫过的运动管道"。多旋翼/固定翼的转弯半径、爬升率这类约束，只有到这一层才真正被满足。

### 1.4 求解规模化：优先级搜索与大邻域搜索

- **PBS**(Searching with Consistent Prioritization) [7]：不搜约束，搜**部分优先序**。发现 `aᵢ`、`aⱼ` 冲突就分裂成 `i≺j` 与 `j≺i` 两支；低层按拓扑序逐机规划，低优先级把高优先级的时空占用视为障碍。放弃最优性换速度，也系统地讨论了优先级规划在完备性/最优性上的天花板。多数 UTM 工程原型实际用的是这套骨架。
- **MAPF-LNS2** [8]：允许先拿一组**带碰撞**的路径当起点，然后反复挑一小撮"仍在碰撞"的飞机构成邻域，把它们的路径拆掉、用 SIPP 变体以"尽量少与他人碰"为目标重解，直到碰撞数归零。这是"**局部修复**"原语——后面讲动态重规划时它是主力。

### 1.5 落到低空 UTM：三条系统性工作

**(a) 空时图直接做 UTM 路径服务。** [11] 把地图先离散成单位图、再时间展开成离散空时图，**批处理**路由请求，目标函数是"被成功受理的请求比例"——本质是时空资源的批量分配而非单机最短路。[12] 把它推广到运营人用**航路点组序列**描述任务（每组过一个即可，对应多充电站/多取送点），在空时图上做多源多汇搜索。[13] 再加上**动态重路由**：轨迹按构造无冲突、支持变速，运行中出现偏差、通信异常或临时空域限制时，只对受影响航段在空时图上重新求解并重新预约。这三篇是同一条系统线（离散空时图 → 预约 → 批量受理 → 动态重路由），读机制最连贯。

**(b) 把 MAPF 直接当作 UTM 的预飞 CDR。** [14] 明确指出中心化 UTM 在体制上不现实，于是把 CDR 做成 **USSP(服务提供商)之间的迭代协商**：各自本地规划，交换会冲突的计划，按谈判协议逐轮互加约束直到全局无冲突。[15] 则指出标准 MAPF 的两个假设——起飞时刻固定、速度均匀——在 UTM 里都不成立，于是把**起飞时刻与巡航速度也变成决策变量**塞进求解器。几何上等价于允许整条时空路径"沿时间轴平移 + 拉伸"，可解实例数因此大幅提高。**"调度"与"路径规划"耦合在这里，这也是"无人机群调度"区别于普通 MAPF 的地方。**

**(c) 从格点占用升级到 4D 体积与交通流。** U-space/UTM 的工程语义不是"点"而是**运行体(operational volume)**：沿航路把一段时间内飞机可能出现的空间包络串成一条 4D 契约链，战略去冲突就是让不同运营的运行体链在 4D 上互不相交 [16]。交通流层面则要处理时间的**随机性**：[17] 提出 **waypoint occupancy time(WOT)**——某航路点被某架飞机占用的时间段本身是随机变量；用机会约束写"两架占用同一航路点的时间窗重叠概率 ≤ ε"，再把概率约束确定化成带分位数余量的确定性时间窗，从而得到风险有界的间隔保证；扰动发生时以 reactive 方式重优化被打乱的 4D 轨迹，同时以 proactive 方式提升后续鲁棒性。

另有一支是运筹味更重的**时空网络 + 对偶分解**：[18] 把速度、时变影响区都编码进离散时空网络，写成整数规划，用拉格朗日松弛把耦合的多机问题分解成一串"时变最小费用路"子问题——如果你说的"时空图"指的是这一支，这篇是最清楚的入口。

## 2. 强化学习这条线：避碰是怎么被"学"出来的

### 2.1 统一的建模模板

几乎所有这类工作都是同一个 Dec-POMDP 模板，看论文时按这四项对照即可：

- **观测**：自身状态（到目标的相对位置、速度、机体半径）+ 邻近飞机的相对状态（相对位置/速度/半径/最小间隔要求），或直接用原始传感（激光、深度图、局部占据栅格）。
- **动作**：速度/航向/高度增量（连续），或离散机动集。
- **奖励**：到达奖励 − 时间惩罚 − 碰撞重罚 − 逼近最小间隔的连续惩罚（常再加航迹偏差、能耗、机动幅度项）。
- **训练/执行结构**：集中训练分散执行(CTDE)，多机共享同一套同构策略参数。

### 2.2 反应式避碰的两块基石

- **CADRL / Socially aware motion planning** [20]：学的是两体交互的**价值函数** `V(s)`，在线用一步前瞻加学到的 `V` 来选动作。机制上等价于把 ORCA 那种手写几何规则换成"从数据里学出来的合作代价"；论文的另一个贡献是把"靠右通过"这类社会规范用奖励项诱导出来，而不是硬编码。
- **Long et al.** [21]：sensor-level 端到端，把 2D 激光原始读数直接映射到速度指令，多机并行采样 + PPO 训练，**不需要他机状态估计，也不需要通信**。这是"端到端反应式避碰"的标准基线，后续多 UAV 工作大量沿用它的奖励与课程设计。

### 2.3 学 MAPF：把集中式规划蒸馏成分布式策略

- **PRIMAL** [22]：每架只看以自己为中心的局部视野（多通道张量：障碍层、他机层、他机目标层、自身目标方向层），用 **RL + 模仿学习**联合训练——模仿的是集中式(近)最优规划器的行为，RL 负责在专家覆盖不到的状态上兜底；并显式加入"阻塞惩罚"抑制自私行为。推理是一次前向传播，因此**每一步都可以重规划**，这正是它相对集中式求解器在动态环境下的核心优势。
- **PRIMAL₂** [23]：面向 lifelong（目标不断刷新）场景扩展，强化了走廊/瓶颈这类结构上的约定与观测编码，使策略在长时间连续作业中不退化。

### 2.4 邻居数量可变与置换不变：注意力与图神经网络

低空里"周围有几架飞机"是变化的，普通固定维 MLP 无法处理，这是 RL 侧最实质的技术困难，两条主流解法：

- **MAGAT** [24]：把"谁跟谁通信"建成图，用**图注意力**做消息聚合，让每架给不同邻居分配不同权重（普通 GNN 的均值聚合会把关键邻居的信息淹没）。数据流是：CNN 抽局部地图特征 → GNN 做 K 跳邻域通信 → MLP 出动作；小规模训练可泛化到大规模。
- **Brittain & Wei 系** [25]：面向高密度扇区且**目标异构**（不同速度、性能、目的地）的分布式 MARL。每架飞机是一个 agent，观测含自身与最近若干架入侵机的相对状态，用注意力/循环结构吸收"入侵机数量可变"，并显式学习入侵机**意图**——异构场景下不估意图就无法安全让行。

### 2.5 与调度/搜索的耦合：这是低空场景最该看的一类

- **Integrated Conflict Management for UAM** [26]：直接回答"时空图式的调度和 RL 怎么配合"。核心观察是 **RL 战术去冲突的性能强依赖交通密度**，所以先用战略**需求容量平衡(DCB)** 把密度压回 RL 训练分布内，再让 RL 做战术去冲突。这是分层耦合而非二选一。
- **LNS2+RL** [28]：反过来把 RL 嵌进搜索。先用 MARL 策略把"碰撞很多"的解快速修到"碰撞很少"（学习负责全局粗修），再切到 MAPF-LNS2 的 SIPP 修复把剩余碰撞清零（搜索负责收尾保证）。这是目前"学习 + 搜索"配比最清楚的一篇。
- **3D RVO-enhanced MARL** [27]：把几何判据当奖励塑形。用三维互惠速度障碍刻画冲突区，把 RVO 区域、航迹偏差、碰撞时间预测、速度保持写进多目标奖励；网络处理可变维输入，actor-critic 优化。结构化空域(走廊/航路网)下的结果最直接可比。

### 2.6 安全兜底：学出来的策略不能裸奔

- **GCBF+ / Neural Graph CBF** [29]：用图结构定义 **graph control barrier function**，每架只用局部邻居信息；再用 GNN **同时**学 GCBF 证书和分布式控制器，训练时强制 CBF 条件成立。得到的是可扩展、可泛化且带安全证书的分布式避碰控制，工程上通常作为 RL 策略输出之上的**安全滤波层**。
- 面向低空具体扰动的例子：[30] 处理"临时禁飞区/geo-fence 突然出现"叠加密集建筑的城市场景，用 DDPG 类连续控制框架同时应付静态障碍与动态涌现的限制区——这是典型的**反应式动态重规划**。

## 3. 动态重规划：四种机制，不要混为一谈

**机制 A｜滚动时域整体重解(rolling horizon)。** **RHCR** [9] 是最清楚的形式化：把 lifelong MAPF 分解成一串**窗口化 MAPF** 实例，只保证**前 `w` 个时间步**无冲突，`w` 之外的冲突暂时忽略；每 `h ≤ w` 步重解一次，把新任务、新位置、新约束灌进去。`w` 控安全裕度与计算量的折中，`h` 控重规划频率。UTM 里"每隔若干秒滚动重算一次战略方案"就是这套东西。低空的 4DT + DCB 版本见 [19]。

**机制 B｜局部修复(plan repair)。** 不动没受影响的飞机，只重规划受扰动波及的子集——MAPF-LNS2 [8] 的邻域选择与修复算子就是原语，[28] 给出学习加速版。相比整体重解，代价低一到两个数量级，是高频扰动下的现实选择。

**机制 C｜执行层保序，不重规划也不碰。** **ADG(action dependency graph)** [10] 的机制非常值得单独理解：它把 MAPF 解**编译**成一张动作依赖图——保留"谁必须在谁之前离开某个位置"的**偏序**，丢掉绝对时刻。执行时只要满足偏序，任一架变慢、悬停、临时避让，后面的自动等待，不会引发连锁碰撞；而且**重规划可以与执行重叠**，通信需求极低。把"时刻表"换成"时序契约"是低空执行层最实用的一招。

**机制 D｜机载战术兜底。** 战略方案失效、或遇到非合作目标时，最后一道是秒级机载策略：RL 策略 [21][25][27][30]、几何法或 MPC（见下节）。

**典型数据流**（把上面四条串起来）：
```
运行申请 → 空域离散化(走廊图/栅格) → 时间展开成时空图
        → 批量/优先级/CBS 求解 → 4D 运行体契约下发
        → 执行监控(位置偏差、风、临时禁飞、通信中断)
        → 触发 A/B/C/D 之一：
             整体滚动重解(RHCR) | 局部修复(LNS2) | ADG 保序等待 | 机载 RL/几何避让
        → 回写预约表 / 更新运行体
```

## 4. 对照组：几何与优化型的在线避碰

读 RL 论文时这三篇是必需的比较基线，机制也最容易讲清：

- **ORCA / Reciprocal n-Body Collision Avoidance** [31]：对每一对飞机，在**相对速度空间**里割出一个半平面（互惠原则——各自承担一半避让责任），所有半平面求交得到可行速度集，再在其中选最接近期望速度的那个。求解是一个小线性规划，微秒级、无需通信。代价是无全局最优、密集场景易死锁。
- **DMPC** [32]：每架在滚动时域上解一个小 QP，用**按需碰撞约束**（只在预测到会碰的时刻才加约束，而不是全时域加），并用**事件触发重规划**应对扰动；与缓冲 Voronoi 元胞(BVC)相比通行时间显著更短、高密度下成功率更高。
- **EGO-Swarm** [33]：完全分布式、异步、纯机载。碰撞风险写成非线性优化的**惩罚项**而非硬约束，几毫秒生成安全、平滑、动力学可行的轨迹；靠一个**不可靠的**轨迹共享网络交换他机轨迹，并在线检测与纠正相对定位漂移。这是"机载算力 + 无中心 + 高频重规划"的代表实现。

## 5. 阅读路线建议

- **只想快速理解时空图怎么避碰**：[1] → [2] → [4] → [5]（四篇按顺序读，机制是层层递进的：预约表 → 约束树 → 安全区间 → 连续时间）。
- **想看它在低空/UTM 里的完整系统形态**：[11] → [12] → [13]（同一条系统线），再补 [14][15]（分布式协商与"起飞时刻+速度"入决策）、[16][17]（4D 运行体与随机占用时间）。
- **想快速理解 RL 怎么避碰**：[21]（端到端基线）→ [22]（RL+模仿学 MAPF）→ [24]/[25]（可变邻居数的注意力与 GNN）。
- **想看两条线怎么合**：[26]（战略 DCB 压密度 + 战术 RL）与 [28]（RL 粗修 + LNS 收尾）是目前讲得最透的两篇。
- **安全性怎么保证**：[29]（图控制障碍函数作安全滤波层）。
- **综述**：[34]（UTM 冲突探测与解脱全景）、[35]（MAPF 经典与学习两条路线的对照）。

**一句话总结机制差异**：时空图这条线的做法是"**把碰撞变成图上的资源占用冲突，再用约束/优先序/局部修复把冲突消掉**"，它的动态性来自滚动窗口、局部修复和执行层偏序；强化学习这条线的做法是"**把碰撞变成奖励里的负项，让策略在局部观测下学出让行行为**"，它的动态性天然来自每步 O(1) 的前向推理，但需要注意力/GNN 处理可变邻居数，并需要 CBF 之类的安全层兜底。低空无人机群调度的现实答案不是二选一，而是[26][28]那种"战略用图搜/优化定 4D 契约、战术用学习策略吸收不确定性"的分层耦合。
