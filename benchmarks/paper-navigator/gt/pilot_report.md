**结论:6 题全部用满 15 轮上限,无一达到"连续两轮零新增"的严格饱和。你此前判断 5-6 轮不够,完全正确,而且差距比预想大。** 两个结构性原因:

1. 热门领域(Q001)文献密度太高,单角度查询就返回 100-200 条,靠加轮数逼近全量不现实;
2. 晚轮的大丰收(Q059 R9=36)不是"再挖一铲",而是**换检索模态**(改用 venue 过滤 + 引用量排序的 bulk 扫库)带来的——说明提升覆盖率的杠杆是模态编排,不是轮数本身。

| 选项 | 配置 | 估算(64 题) | 判断 |
|---|---|---|---|
| A | 照试点:15 轮顶格 | ≈1520 万 token,约 7 小时 | 已验证可用,综述类留少量尾巴 |
| **B(推荐)** | 18 轮上限 + 双零即停,**并把 bulk 扫库/引文图前移到第 2-4 轮**(Q059/Q036 的教训) | ≈1600-1800 万 token,约 7-8 小时 | 模态前移让高产轮早发生,多数题会在 18 轮内自然停 |

## 五、质量观察

- 答案形态达标:中文结构化综合、引用密集、按题型出形态(时间线/对比表/机制分层/跨学科链条),并主动给出"研究空白"与"不可比性"提示(如 Q001 指出各论文 SWE-bench 数字因 backbone/harness 不同不可横比)。
- GT 层面有实质发现,复核时可当锚点:Q012——**不存在**同一真实数据集上 GNN vs 序列 Transformer 的正面对比,规则引擎几乎从不作为调优基线;Q018——**没有**公开研究对比同一批模型的榜单排名 vs 实路闭环排名;Q036——没有论文把 Assmann 文化记忆理论形式化为 KG 本体。这类"负结论"对 benchmark 打分设计很有价值(技能若编造此类对比文献,直接可判)。
- 中文文献是 S2 的系统性盲区:Q006/Q036 的关键中文文献全靠网页检索 + 出版方页面救回。正式批必须保留网页通道(与"用任何有用工具"的决定一致)。

## 六、正式批(64 题)执行改动清单

1. **scratchpad 隔离**:3 个 agent 报告 /tmp 共享文件被并发覆盖(均自行发现并规避)。正式批 prompt 直接规定每题私有工作目录。
2. **检索模态编排前移**:bulk 扫库(venue + 引用量排序)与引文图遍历提前到第 2-4 轮;S2 长 query 会返回空,提示用短语式查询。
3. **arXiv API 不作依赖**:试点中持续 429(Q018),S2 + 网页已足够;要用就 https + 跟随重定向。
4. **并发与限速维持**:6 并发 + 单 agent S2 调用 6 秒间距,全程仅 1 次 429;64 题按 6-7 题/批滚动。
5. **中文期刊链接规范**:优先刊物官网文章页,慎用未注册 DOI(本次唯一 DEAD 即此因)。
6. 轮次预算按你在第三节选定的选项执行。
